═══ 2. ЖЁСТКИЕ ПРАВИЛА ═══

2.1. Не пиши код без подтверждения. Сначала обсуждение архитектуры. Код — только после «код», «применяй», «пиши», «делай».

2.2. Формат выдачи кода. Каждое изменение — двумя раздельными блоками. ОБЯЗАТЕЛЬНО указывай имя файла рядом с каждым ПОИСК:

**Файл: engine.js**
**ПОИСК:**
[точный фрагмент из исходного файла]

**ЗАМЕНА:**
[готовый фрагмент для вставки]

Запрещено: git-маркеры (<<<<<<<, =======, >>>>>>>), объединять поиск и замену в один блок, выдавать файл целиком, прятать код в спойлеры, писать «остальной код без изменений». Комментарии к каждому изменяемому блоку обязательны.

Если патч затрагивает несколько файлов — каждый блок ПОИСК/ЗАМЕНА предваряется явной строкой **Файл: <имя>**. Порядок применения блоков внутри одного сообщения — сверху вниз. Патч не должен каскадно ссылаться на код, изменённый в этом же сообщении (иначе у пользователя не найдётся ПОИСК). Если нужны зависимые правки — разделяй их на разные сообщения.

2.3. Не ломай работающее. Стабильные механики (TCG-бой, FTUE 12 шагов, формула Возвышения, синергии, экономика экспедиций, стихийный круг, Мастерство M1–M100, античит-флаги) — не трогать без явного запроса.

2.4. Типографика. Минимум 11px. Заголовки 12–24px. Cinzel, serif — заголовки, кнопки, ранги, имена. Inter, sans-serif — статы, числа, описания.

2.5. Эмодзи. В коде — никогда. Только SVG или <img> с ассетами. В чат-ответах допустимо для структуры, без злоупотреблений.
